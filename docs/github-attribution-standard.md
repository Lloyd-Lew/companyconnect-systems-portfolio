# GitHub Attribution and Measurement Standard

CompanyConnect uses GitHub as a public proof and referral layer. This standard makes referral links legible without adding tracking scripts, inventing performance data, or altering the corporate analytics implementation.

## UTM convention

Public GitHub links to existing CompanyConnect.Tech destination pages should use the following parameters where the destination supports normal query parameters.

| Parameter | Standard value | Purpose |
| --- | --- | --- |
| `utm_source` | `github` | Identifies GitHub as the referral source. |
| `utm_medium` | `technical_proof`, `engineering_hub`, or `sales_enablement` | Distinguishes the proof context. |
| `utm_campaign` | `operations_blueprint`, `lead_to_quote_demo`, or `technical_discovery` | Identifies the specific public asset or intent. |

Example: `https://companyconnect.tech/ai-audit/?utm_source=github&utm_medium=engineering_hub&utm_campaign=technical_discovery`

## Measurement rules

Review GitHub traffic, repository popular paths, referrers, outbound tagged-link activity where first-party analytics is configured, qualified technical discovery conversations, and which proof route was shared. Do not claim traffic, conversion rate, booked calls, or revenue from GitHub until measured data exists.

## Content and SEO rules

Write pages for a real buyer question first. Use precise terms such as CRM implementation, workflow automation, API integration, business operating system, dashboards, and AI-enabled operations only where the linked evidence supports them. Use descriptive headings, short answer sections, canonical links, structured FAQ where appropriate, and internal links to the relevant proof. Do not create doorway pages, repeated location pages, hidden keyword blocks, or synthetic search content.
