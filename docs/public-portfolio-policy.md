# Public Portfolio Policy

CompanyConnect.Tech uses this repository as a curated proof layer for prospective clients, collaborators, and referral partners. It is not a raw project archive.

## What belongs here

Public material should help a visitor understand a delivery pattern, engagement path, operating method, or client-safe business insight. Examples include anonymised system patterns, process guides, package decisions, measurement approaches, and approved visual diagrams.

## What never belongs here

The following information must remain private unless written client permission, a documented legal basis, and a complete safety review say otherwise:

| Do not publish | Reason |
| --- | --- |
| Client names, contacts, records, or identifiable operating data | Confidentiality and privacy |
| API keys, access tokens, webhook URLs, passwords, or workspace links | Security and access control |
| Raw exports of client automations, boards, workflows, dashboards, or documents | They can disclose implementation detail, structure, or hidden data |
| Screenshots containing live systems or customer information | They can expose confidential data even when the main content appears harmless |
| Unverified results, claims, or testimonials | Public proof must remain accurate and defensible |

## Publishing gate

Before adding a public asset, confirm each answer is “yes.”

1. Does the asset explain a real delivery pattern or buyer decision?
2. Is every business claim accurate, current, and supportable?
3. Has client-specific material been removed, anonymised, or explicitly approved?
4. Does the asset contain no credentials, access routes, live links, or sensitive records?
5. Does it link to the appropriate service, package, audit, or strategy-call next step?

If any answer is “no,” keep the material private until the gap is resolved.
